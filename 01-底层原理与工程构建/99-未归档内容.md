# 1. GPIO 简介

在单片机中最开始打交道的就是 GPIO 口，全称 General-Purpose Input/Output。其作用也是比较粗暴简单，就是可以向外部输出逻辑 1/0，也可以设置为接受外部逻辑 1/0 的输入。然后配合硬件电路和总线，存在有推挽输出/开漏输出，浮空输入/上拉下拉输入集中不同的情况。

1. 推挽输出一般用于点对点设备，对方是一个纯输入，并且电压完全匹配。比如驱动 LED、蜂鸣器，高速通信总线如 SPI 的 SCK/MOSI，或者 UART 的 TX，还有最简单的使能引脚。
2. 开漏输出则是为了解决推挽输出在多节点上出现的不同设备输出 0 和 1，导致实际上芯片内部的电源直接接地导致的短路而实现的。虽然输出 0 依然是接地，但是输出 1 时依靠上拉电阻(内部浮空不接电源)，避免了短路。另外还有一个用法就是实现电平的匹配，用浮空 + 上拉电阻实现对更高电压的器件的驱动。

输入的情况类似，根据具体的情况进行选择就好。

## 1.1. GPIO 的内核开发

单片机中的 GPIO 使用比较粗暴，可以认为是“裸奔”，可以对 GPIO 口进行初始化配置和操作，库函数直接提供对应接口。上层的功能全部需要自己去实现(GPIO具体干什么事情)。

而在 Linux 中显然不能也不许直接操作 GPIO 引脚，而是通过一系列抽象和封装为开发者提供接口。

# 2. `/proc` 目录简介

## 2.1. `/proc` 目录是什么

用户程序或者命令行如何获取当前计算机的一些信息和状态呢？内核提供了一个 `/proc` 目录。它是一个**虚拟文件系统**，只存在于内存中，不占用磁盘空间。本质上它就是一个**内核数据结构的接口**，让用户和程序能够以一种统一、标准的方式来获取信息。它的主要用途分为两点：

* **查看系统运行状态**：`/proc` 目录下有大量的只读文件，用于展示内核、硬件及进程的实时信息。
* **动态调整内核参数**：`/proc/sys` 下部分文件是可写的吗，允许在不重启系统的情况下，动态修改内核的运行行为。

## 2.2. 对比一下几个目录

| 目录 | 文件系统类型 | 核心作用 | 内容来源 |
| ---- | ---- | ---- | ---- |
| `/proc` | `procfs`虚拟 | 提供**进程**和**内核**的运行时信息与状态 | 内核动态生成 |
| `/dev` | `devtmpfs`虚拟 | 提供**设备文件**，用于与硬件设备进行交互 | 内核管理，代表设备 |
| `/sys` | `sysfs`虚拟 | 导出**内核对象**(如设备、驱动、总线)的层级信息 | 内核数据结构 |


## 2.3. `/proc` 目录有什么

该目录下的内容比较规整：

* **以数字命名的目录**：其实就是以进程 ID (PID) 命名的目录。进入这些目录可以查看对应 PID 的进程详细信息，例如：
  * `cmdline`：启动该进程的完整命令。
  * `cwd`：进程当前的工作目录。
  * `environ`：进程的环境变量。
  * `exe`：指向实际执行文件的符号链接。
* **提供系统信息的文件**：这些文件直接放在 `/proc` 目录下，提供了各种内核和硬件信息。比如提供 CPU 运行信息的 `/proc/stat`，还有：
  * `/proc/cpuinfo`：CPU 的详细信息。
  * `/proc/meminfo`：物理内存和交换分区的使用清空。
  * `/proc/uptime`：系统启动后运行的时间和空闲时间。
  * `/proc/version`：当前内核的版本信息。

7. `procs_blocked` 行：等待 I/O 操作完成的进程数。

# 3. eMMC 驱动架构理解：硬件与主机控制器关系总结

## 3.1. 问题的提出

在实际查看 Linux 内核中有关 EMMC 驱动的时候，会发现一些奇怪的专有名词。从 dts 文件入手，我们搜索 `mmc` 会得到这样的节点：

```c
  aliases{
    mmc0 = &sdhci;
  }

	sdhci: mmc@fe310000 {
		compatible = "rockchip,rk3568-dwcmshc", "rockchip,dwcmshc-sdhci";
		reg = <0x0 0xfe310000 0x0 0x10000>;
		interrupts = <GIC_SPI 19 IRQ_TYPE_LEVEL_HIGH>;
		assigned-clocks = <&cru BCLK_EMMC>, <&cru TCLK_EMMC>,
				  <&cru CCLK_EMMC>;
		assigned-clock-rates = <200000000>, <24000000>, <200000000>;
		clocks = <&cru CCLK_EMMC>, <&cru HCLK_EMMC>,
			 <&cru ACLK_EMMC>, <&cru BCLK_EMMC>,
			 <&cru TCLK_EMMC>;
		clock-names = "core", "bus", "axi", "block", "timer";
		resets = <&cru SRST_C_EMMC>, <&cru SRST_H_EMMC>,
			 <&cru SRST_A_EMMC>, <&cru SRST_B_EMMC>,
			 <&cru SRST_T_EMMC>;
		reset-names = "core", "bus", "axi", "block", "timer";
		status = "disabled";
	};
```

这里我们使用的 EMMC 的设备节点名字叫做 `sdhci`，而驱动的 `compatible` 字段匹配中还有一个 `dwcmshc`。这些都是什么？ 

## 3.2. 核心概念区分

| 术语 | 全称 | 本质 | 角色 |
|------|------|------|------|
| **eMMC** | Embedded Multi‑Media Card | **实体存储芯片**（如三星、铠侠的闪存颗粒） | **从设备**（被控制） |
| **主机控制器 (Host Controller)** | 集成在 SoC 中的硬件模块 | 负责发出电信号和协议命令控制 eMMC | **主设备**（发出指令） |
| **SDHCI** | Secure Digital Host Controller Interface | **软件接口标准**（定义寄存器布局、中断、操作流程） | **通用驱动框架**（`sdhci.c`） |
| **dwcmshc** | DesignWare Cores Mobile Storage Host Controller | 特定硬件 IP（Synopsys 设计）在 Linux 中的**具体驱动实现** | **平台驱动**（`sdhci-of-dwcmshc.c`） |

## 3.4. 为什么驱动不直接叫 “emmc”？

- **职责分离**：`eMMC` 描述的是存储**设备**，而驱动是控制**主机控制器**，两者不同。
- **标准与实现**：`eMMC` 是物理和协议标准；驱动更多关注 **软件接口标准（SDHCI）** 和 **具体硬件实现（dwcmshc）**。
- **历史兼容性**：`sdhci` 框架最初为 SD 卡设计，后续兼容 eMMC/MMC，采用统一接口便于复用。
- **命名清晰**：`dwcmshc` 明确指出了硬件来源（Synopsys DesignWare），利于维护。

---

## 3.5. 设备树节点描述的对象

- **设备树中的节点通常描述的是“主机控制器”**，而非 eMMC 芯片本身。
- **为什么没有 eMMC 的子节点？**
  - **动态发现**：eMMC/SD 设备遵循 MMC/SD 协议，内置了标准识别流程。内核可通过命令自动获取制造商、容量、分区等信息，**无需在设备树中静态描述**。
  - **与 I2C/SPI 的区别**：
    - I2C/SPI 总线上的外设**无统一发现机制**，因此需要设备树静态描述（子节点标明地址、兼容性等）。
    - eMMC 作为存储设备，是系统的“根”之一，被抽象为**块设备**，位于设备树分支末端，通常不再细分。
  - **特殊场景**：若需在设备树中描述 eMMC 卡本身或预定义固定分区，可以使用 `compatible = "mmc-card"` 和 `fixed-partitions`，但在主流开发板中并不常见。

---

## 3.6. 总结类比（便于记忆）

将 eMMC 系统比作 **“插座与电器”**：

| 概念 | 类比 |
|------|------|
| **eMMC 存储芯片** | 墙里的 **电线**（被供电的设备） |
| **主机控制器 (Synopsys DW IP)** | 墙上的 **物理插座**（供电者） |
| **SDHCI 标准** | 国家统一的 **插座尺寸标准**（确保兼容） |
| **dwcmshc 驱动** | 厂家为了生产该特定品牌插座而绘制的 **生产图纸** |

> **核心要点**：`dwcmshc` 驱动只管“插座（主机控制器）”本身如何工作；至于“电线（eMMC 芯片）”的具体信息，由 `sdhci` 协议通过命令探测获得，不由 `dwcmshc` 直接关心。

---

## 3.7. 常见问题快速回答

**Q1：设备树中的 eMMC 节点是描述芯片还是控制器？**  
→ 描述的是**主机控制器**，其属性（如时钟频率、总线宽度）用于配置控制器，而非存储芯片。

**Q2：为什么不像 I2C 那样有子节点？**  
→ 因为 eMMC 支持动态协议识别，无需静态描述；而 I2C/SPI 外设通常无此能力。

**Q3：如果我非要描述 eMMC 的子节点可以吗？**  
→ 可以，使用 `compatible = "mmc-card"` 和 `fixed-partitions`，但非必需，且一般不推荐。

# 4. 网络架构与 Socket 浅析

```
普通网线(RJ45 接口)   \
                      PHY 芯片  ---  GMAC   ---  SoC
      光模块          /         MDIO     平台总线
```
