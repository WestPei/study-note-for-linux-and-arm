# 1. ARINC 717

## 1.1. ARINC 717 数据帧结构

ARINC 717 其实定义了一系列的硬件标准和电气连接标准，主要是用于升级原来的 模拟输入飞行数据采集(ARINC 573)，变为数字输入。ARINC 429标准则是航空电子设备系统间的通用数据总线(可以这么理解)，而 ARINC 717则是一个专门用于飞行数据记录的协议。

协议中其实对 DFDAU (Digital Filght Data Acquisition Unit，数字飞行数据获取单元)和 DFDR (Digital Flight Data Recorder，数字飞行数据记录仪)这两个硬件设备额也有各自的要求。但是这里学习 ARINC 717 更多是为了了解其数据传输的协议。也就是数据帧是怎么样的。这对软件来说才是比较重要的。

具体在 ARINC 717协议文档的 `5.3 Output Data Format` 中对数据结构有详细的定义。

## 1.2. 717 输出数据格式

> Frame Structure
> The basic outputs should have the data organized into a "Frame" which is repeated every four seconds. Each frame should consist of four "Subframes" which occupy one second each. Each subframe consists of 64 (basic rate), 128, 256, 512, or 1024 12-bit words depending on the data word rate specified for the system. Discrete data may be packed into discrete words or assigned as part of an analog data word.


DFDAU 的基本输出是以每 4 秒为一“帧”，而每一“帧”是由 4 个 “子帧” 组成，每个“子帧”占 1 秒。根据数据速率的不同，每一个子帧的大小从 64 到最高 1024 个字（每一个字由 12-bit 组成）组成。

> Frame Synchronization
> The first word in each subframe should provide a frame synchronization pattern. This pattern consists of various configurations of the Barker Code and includes identification of each subframe. Specific synchronization bit patterns are shown in Attachment 4
> The octal codes for subframe 1-4 sync words are 1107, 2607, 5107, and 6670 respectively.

这里给出了帧同步的方法，每一帧中，4个子帧的第一个字都会提供一个帧同步模式，这个模式由不同的 Barker 编码配置组成，包含了不同帧的标识。具体需要参考文档的附件 4。

## 1.3. 附件四-717 数据帧描述

1. One frame of data contains four subframes each with 64-1024 words, each with 12 bits.
2. The frame is repeated every four seconds with a bit rate of 768-12288 Hz.
3. There is one subframe per second. The timing tolerance is 0.1%.
4. The subframes are numbered one to four from the beginning of each subframe.
5. The bits are numbered from ont to twelve from the beginning of each word.
6. Bit number twelve one is the least significant bit(LSB) and transimitted first.
7. Bit number twelve is the most significant bit(MSB) and transmitted last.
8. Word number one of each subframe is the synch word. The synch words are specified by this Characteristic.
9. Subframe One Sync word   -   MSB 001 001 000 111 LSB; Octal 1107
10. Subframe Two Sync word    -   MSB 010 110 111 000 LSB; Octal 2670
11. Subframe Three Sync word    -   MSB 101 001 000 111 LSB; Octal 5107
12. Subframe Four Sync word   -   MSB 110 110 111 000 LSB; Octal 6670
13. All words except for word 1 contain data as assigned by the ROM described in Section 5.1.2.
14. Words may be identified as, for example
15. ALL/33: word 33 of all four subframes
16. 1/3: Subframe one, word 3
17. 1,3/16: Subframe one, and three, word 16
18. ALL/18, 50: Words 18 and 50 of all subframes.
19. Bites may be identified as, for example
20. ALL/6/1: Bit 1(LSB) of word six in all subframes.
21. 1/14/4-6: Bits four to six of subframe one, word 14.

# 2. HI-3717A 芯片

这是一个通过 SPI 总线与 SoC 连接，然后实现 ARINC 717 数据转换的芯片。核心就是通过 SPI 传递指令，然后接收数据或者发送数据。

每一次读/写操作都是以一个 8 bit 的指令为起始。每次传输时，从 MSB(most significant bit，高位) 位开始传输，也就是 bit 7。它具体标识此次操作是读(1)还是写(0)。

该芯片的功能主要就是可以通过识别 717 数据的同步标志，从而实现自动的数据帧对齐(4 同步字和 2 同步字)；当然也可以只负责接收数据到 `Receive FIFO`，然后用户自己负责同步。前辈已经实现了 Hi-3717A 芯片的应用层驱动(基于 SPI 内核驱动)。我们可以基于该应用层代码来进行功能的解读。

## 2.1. 基础 SPI 指令

该芯片是通过 SPI 总线与 SoC 进行通信，因此下发的指令也是走 SPI 总线。下面给出基本的操作指令：

| OP Code | R/W | Data bytes | DESCRIPTION |
| -------|------|------------|-------------|
| 0x64 | W | 1 | Write Control Register 0 |
| 0x62 | W | 1 | Write Control Register 1 |
| 0x6A | W | 1 | Write Receiver FIFO Status Pin Assignment Register |
| 0x72 | W | 2 | Write Word Count Utility Register |
| 0x74 | W | 2 | Write Transmit FIFO word |
| 0x2* | W | 1 | Fast Write Transmit FIFO Word |
|||||
| 0xE4 | R | 1 | Read Control Register 0 |
| 0xE2 | R | 1 | Read Control Register 1 |
| 0xE6 | R | 1 | Read Receive FIFO Status Register |
| 0xE8 | R | 1 | Read Transmit FIFO Status Register |
| 0xEA | R | 1 | Read Receive FIFO Status Pin Assignment Register |
| 0xF2 | R | 2 | Read Word Couont Utility Register |
| 0xF6 | R | 2 | Read Receive FIFO Word |
| 0xFE | R | 4 | Read Receive FIFO Word and Word Count |
| 0xC* | R | 1 | Fast Receive FIFO |

这是基本的一些指令。需要重点关注其中设计到的一些寄存器：

1. CTRL0: Control Register 0，控制寄存器 0，设置 717 数据收发速率、变化率以及选择编码模式。
2. CTRL1: Control Register 1，控制寄存器 1，具有软中断位，同时可以设置同步模式以及测试模式(回环测试)。
3. RXFSTAT: Receive FIFO Status Register，接收缓存状态寄存器，具有接收同步标志位，以及一些接收状态相关的位。
4. TXFSTAT: Transmit FIFO Status Register，传输缓存状态寄存器，可以判断传输队列状态(如是否为空)。
5. FSPIN: FIFO Status Pin Assignment，缓存状态引脚分配寄存器，用于配置两个外部引脚的功能，让 SoC 可以通过读取引出的 RFIFO 和 TFIFO 引脚(注意不是指对应的缓存)来判断对应缓存的状态。(避免频繁使用 SPI 总线读取寄存器)
6. WRDCNT: Word Count Utility Register，可以配置 RFIFO 中存放有特定子帧的特定字数的数据时在 MATCH 引脚上产生中断信号。
